# 目标权重换算

`size` 使用明确的历史可用价格，将只做多的目标权重换算为股数计划。
它不撮合，也不维护第二套账户。

```sh
cargo run --locked -- size fixtures/sizing.json
```

样例以人民币 1000 元、参考价 10 元、10 个基点费用规划买入。
理想数量为 100 股，考虑费用后计划买入 99 股，预计剩余现金 9.01 元。
结果分别保留理想数量和计划数量，便于看清整手与费用造成的偏差。

请求使用 sizing_request.v1。需要币种、现金、费率、信息时间，以及每个标的的
已有股数、参考价、价格时间、目标权重和买入单位。所有标的必须明确列出，
包括目标权重为零、准备卖出的持仓。权重非负且总和不超过一。
价格时间不能晚于信息时间，不能用未来执行价格换算今天的订单。

按标的稳定排序，先规划卖出，再规划买入。买入按整手向下取整并预留费用。
完整清仓可处理已有零股。输出为十进制字符串，保留目标数量、计划数量与预计现金。

预计卖出收入可以用于计划买入，但调用方必须先等待实际卖出并核对真实账户。
下一时刻的价格和成交量未知，计划不保证目标权重能够实现。
执行引擎仍使用实际可用资金检查订单，可能拒绝计划中的买单。

订单 ID 在单个计划内确定。合并同一信息时间的多个独立计划时，需要分配不同 ID。
完整字段和约束见[英文页面](sizing.md)。
