# 公司行为兼容记录

本次核实了 NautilusTrader 0.66.0 的公开缓存调整接口，尚不能将其直接视为完整的
分红和送转股处理。相关场景继续使用 quant-platform 的原始股数公司行为后端。

## 可复现结果

```sh
cargo test --locked quantity_adjustment_propagates_to_cache_but_does_not_rebase_a_stock_split
```

测试通过真实引擎以 10 美元买入 10 股，再用公开数量调整接口将缓存持仓改为 20 股。
此时开仓成本仍为 10 美元，以 5 美元估值的未实现盈亏为 -100。
真正的二拆一、且市场没有变动时，成本应为 5 美元，未实现盈亏应为零。
测试说明的是佣金数量调整原语不能冒充拆股，并不是说上游宣称它支持拆股却算错。

上游提供 Commission 和 Funding 调整事件，以及账户余额调整接口。
这些接口不能单独证明登记日权益、除权日应收、到账/可交易日释放、成本重置和
回放历史之间已经一致。手动修改平均成本或另记现金会绕过上游回放边界。

## 保留在 Python 的场景

| 场景 | 迁移前需要的证据 |
| --- | --- |
| 现金分红 | 登记日持仓、除息应收、到账日和预扣税 |
| 拆股与送股 | 股数与成本重置、应收和可交易股数、缓存和组合一致性 |
| 零股权益 | 明确的现金替代或交收政策，不能隐式取整 |
| 原始价与复权价 | 不能重复计入现金或股份分配 |
| 退市 | 明确的回收和估值政策，不能任意强制清仓 |

新契约会拒绝公司行为字段或相应能力要求，不会静默忽略。
后续需要可回放的上游成本调整扩展或明确的后端选择，再逐项与 Python 进行对照。
完整原语与实现边界见[英文记录](corporate-action-conformance.md)。
