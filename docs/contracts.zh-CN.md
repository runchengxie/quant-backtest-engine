# 输入输出契约

## 请求 engine_request.v1

所有字段必填，未知字段报错。字段名和数据值不随文档语言改变。

| 字段 | 含义 |
| --- | --- |
| initial_cash | 正数美元字符串，最多两位小数，不超过 10^12 |
| fee_bps | 0 到 10000 的基点费率字符串，最多四位小数 |
| instruments | 唯一标的代码与 0 到 4 的价格精度 |
| quotes | 标的、UTC 纳秒时间、正数买价与卖价 |
| orders | 唯一 ID、标的、信息时间、买卖方向及整数股数 |
| required_capabilities | 需要的能力列表，不支持的能力显式拒绝 |

代码和订单 ID 为 1 到 40 个 ASCII 字母、数字、下划线或连字符。
报价按时间排列，同一标的同一时间不能重复。每个标的必须有估值报价。
时间范围为 Unix 纪元之后至 2100-01-01，调用方需要无损保存 64 位整数。
价格不超过 10^6，单笔股数不超过 10^6。

## 结果 engine_result.v1

结果包含上游名称与版本、能力、美元现金、持仓价值、净值、手续费、订单、成交与持仓。
金额和股数为规范化十进制字符串，例如 `10` 不保证保留为 `10.00`。
订单保留用户 ID，成交使用真实上游的价格、股数、费用与时间。
结果去掉随机事件 ID、机器身份与墙钟耗时，便于重复比较。

没有后续合格报价的订单状态为 NOT_SUBMITTED。已提交订单保留上游状态，
例如 FILLED、DENIED 或 REJECTED。净值等于现金加持仓估值。
v1 结果只记录回测结束时的状态。需要逐日现金、持仓和净值时，使用
[v2 逐日账本](sessions.zh-CN.md)。夏普率和最大回撤等指标由调用方根据结果另行计算。

能力声明为 quote_market_orders、multi_asset、final_balances、proportional_fees。
完整 JSON 与 Rust 类型见[英文契约页面](contracts.md)。
