# 共用账户的策略分配与未完成退出

语言：简体中文 · [English](sleeve-allocation.md)

`quant_backtest_core.planning.sleeve_allocation` 把同一账户已经发生的一批成交归属到各个策略。
通用 `pool_sleeves` 目标合并接口仍属于 Platform。分配工具不持有撮合器、账户、成交量额度
或冲击状态，执行仍由原有模块负责。不同券商账户共用市场流动性需要另一套模型，本接口不支持。

## 声明批次

先调用 `net_sleeve_demands(demands, reference_prices=..., policy="pro_rata")`，
通过原有执行模块处理返回的 `external_orders`，再调用
`allocate_external_fills(net_plan, fills)`。每个策略与证券组合只能提供一条不可变的
`SleeveDemand`，标识不能为空，需求是非零的带符号整数股数，正数买入、负数卖出。
参考价必须是同一账户货币下的正原始价格，且参考价的证券集合必须与需求完全一致。
同一证券使用相同的正整数 `lot_size`，默认一股，需求必须是整手。
即使执行模块支持，分数股权益和特殊零股交易也不属于这个分配契约。

每行都声明 `inventory`、`sellable`、`locked`、`cash_budget` 和 `fee_budget`。
`sellable` 是施加本次锁定前、已经结算且满足其他卖出条件的数量。
`locked` 是其中被锁定的部分，必须满足
`0 <= locked <= sellable <= inventory`。可分配卖出量是
`sellable - locked`，向下取整到整手。整个证券被 `QuantityLock` 限制时，
设置 `locked=sellable`，不能把其他尚未结算的库存也算进锁定子集。
`blocked=True` 同时阻止买卖和内部转移。所供证据必须在整个批次中有效，
限制、库存或预留资金发生变化时应拆批并重新规划，卖出意愿本身不能证明可卖库存。

现金预算是由调用方余额支持的独占行级预留，不能重复分配给其他证券、策略或批次。
调用方负责核对全部预留与账户余额。买入还必须提供不低于参考价的 `max_buy_price`。
先预留全部 `fee_budget`，再按 `(cash_budget - fee_budget) / max_buy_price`
计算数量上限，并向下取整到整手。卖出行不接受最高买价，费用也须从已有现金中预留。
这个保守契约不使用预计卖出或内部转移所得来支持其他买入或费用预留，
也不会从策略意愿推断借款、公司行动权益或可用资金。

## 内部转移和外部成交归属

对每个证券，以符合条件的买卖总量中较小的一方作为内部转移量。
双方分别按整手数量比例分配，先取精确比例的整数部分，再按余数从大到小补足，
余数相同时按策略名称的字典顺序优先分配。内部每股按声明的参考价值转移，
买方增股减现金，卖方减股增现金，现金变化之和严格为零。
内部转移不会生成外部成交，也不产生外部费用、流动性消耗或市场冲击。
每个证券最多留下一个净外部订单，锁定或预算不足的需求保留为未完成部分。

外部成交必须提供 `fill_id`、正整数 UTC 纳秒时钟 `ts_ns`、`symbol`、`side`、
正整数 `quantity`、正原始 `price`、`gross_amount` 和 `fee`。
调用方须把成交标识绑定到实际来源，不能把重复账户快照当成新成交。
数值通过 `Decimal(str(value))` 转换，不做舍入，并在精度为 64 位的精确十进制上下文中核算，
超出可精确表示范围时拒绝。成交额必须严格等于数量乘价格。
费用与费用预留必须是非负的整分，现金和成交额可以保留小于一分的精度。
二进制浮点执行模块的适配器须明确货币规范化规则并保留原始证据，
原始价格与成交额不一致时本工具会拒绝，不能偷偷舍入成另一套现金账。

按 `(ts_ns, fill_id)` 的固定顺序，把每笔成交分配给同方向的剩余需求，
使用相同的整手与余数规则。按该笔实际分配股数，以分为单位分摊真实费用，
余数相同时也按策略名称排序。不会重新计算母订单最低佣金。
同一次调用内完全相同的物理成交标识只计一次，冲突的重复记录会报错。
结果保留规范化后的实际成交证据，跨批次去重由调用方维护。

每笔真实成交都必须匹配计划的证券、方向、可分配数量和整手要求。
每个接收买入的策略都必须满足自身最高买价，累计费用和现金支出必须满足各行预留。
不兼容的成交会使整个纯分配调用失败，调用方输入与真实账户成交保持原样以便核对。
不会截断、漏记成交，也不会为绕过费用预留而改派给其他策略或提交半个批次。

`SleeveAllocation.deltas` 给出内部、外部和总股数变化、现金变化、真实分摊费用，
以及仍未完成的带符号需求。按证券汇总股数等于 `pooled_quantities`，
现金之和等于 `pooled_cash_delta`，费用之和等于 `pooled_fee`，内部现金之和为零。
这些只是批次变化，不是另一套长期账户账本。加到调用方提供的期初策略余额后，
才得到与总账户勾稽的现金和持股。长期损益还需要各自负责模块提供成本基础、估值、权益和资本流。
机会短缺只是描述，不会从现金里再扣一次。

## 手算例子与有限退出

买方要买五股，卖方提供三股，参考价为十，则内部转移三股，买方现金减少三十，
卖方增加三十，最后只需向外买两股。两个策略各要买三股，而实际只成交三股时，
策略 `a` 获得两股，`b` 获得一股。真实费用为五分时分别承担三分和两分，
现金变化分别为负 20.03 和负 10.02，剩余需求分别为一股和两股。
不会独立舍入每个策略的成交额。

合成测试向原有执行模块提交一个合并的一千股订单。
成交量一千股的行情上，10% 参与率只能成交一次一百股。
明确非零的假设永久冲击系数 0.002 使成交价为 10.1、成交额为 1,010、费用为 1，
随后永久状态为 0.2。分配不会再改变执行模块的状态。
这些只是敏感性机制，不是已校准的市场冲击或历史排队证据，零冲击仍是基线选项。

执行前应预先声明观察期限，以及持有、再平衡、只退出或有限期清仓的比较方式。
零目标只是提出卖出要求，不能证明已经退出。
一个实际执行模块测试从一万现金开始，以十元买入五百股。
第二天的显式锁定阻止卖出，最后一天容量只允许卖一百股，最终现金六千、剩余四百股。
把真实现金、剩余股数、应收权益和带时钟及新鲜度要求的估值传给已有
`quant_backtest_core.evidence.execution_integrity.exit_wealth`。
新鲜的十元估值给出账面财富一万、剩余股数账面价值四千，但已实现现金财富仍未知。
剩余估值缺失或过期时，连账面财富也未知。只有无剩余持仓且无未结应收权益的账户，
才有 `cash_realized_wealth`。剩余估值不等于可执行清仓所得。
这里的限制通知与冲击输入均为合成数据，不宣称券商、借券或公司行动校准能力。
