# 可恢复的分钟执行会话

语言：简体中文 · [English](minute-session.md)

`quant_backtest_core.backtest.minute_session.MinuteSession` 复用已有分钟撮合器和经济账本，
支持逐事件推进、恢复、不可变公司行动、永久估值与外部资金流输入，
并提供保守的延迟账户视图。它不实现券商恢复，也不重建历史排队顺序。

## 创建与恢复

提供 targets、bars、`MinuteExecutionConfig`，以及实现 `checkpoint()` 的可调用策略。
可选参数为 `corporate_actions=()`、`valuation_events=()`、`capital_flows=()`、
`quantity_locks=()`、`report_delay_seconds=0` 和 `impact=None`。
旧构造参数仍然有效。从 `quant_backtest_core.backtest.minute` 导入
`CorporateAction`、`ValuationEvent` 和 `CapitalFlow`。
同步接口 `simulate_minute_execution` 接受相同的三类财务事件，使用同一账本。

`step()` 推进一个调度时点，结束前用 `checkpoint()` 保存状态，
用 `run()` 完成运行。根据检查点的 `policy` 字段恢复策略后调用：

```python
restored = MinuteSession.restore(
    targets,
    bars,
    config,
    checkpoint,
    policy=restored_policy,
    corporate_actions=expected_actions,
    valuation_events=expected_valuations,
    capital_flows=expected_capital_flows,
)
```

显式提供的事件序列必须完全匹配。省略某个参数时，便捷恢复模式使用检查点内嵌的序列。
外部作业仍须绑定预期的源文件，并传入预期序列，包括空元组。
仅有内嵌数据不能证明它就是调用方预期的输入。
策略源文件必须可检查。可恢复冲击模型仅接受准确的 `LinearImpact` 类型，
财务事件也只接受明确支持的准确类型。

## 财务时钟与处理顺序

公司行动保持已有的不带时区日历日期契约：
`available_date <= record_date < ex_date`。
登记日收盘持仓产生权益，后续首个有事件的日期确认除权应收款，
并支付已到期现金或释放已可交易股票。日期不会被解释成虚构的历史盘中时刻。
缺少登记日覆盖会报错。合成除权参考价、预扣税、零碎权益、T+1 和费用沿用原有语义。

每个调度时点先结算上一个有事件的交易日、重置 T+1、开启新日并处理到期公司行动，
再依次处理永久估值、外部资金流、订单到期与数量锁。
到期财务报告在决策前送达，随后执行决策、订单进入与行情柱处理。
相同时刻结束的行情柱不能作为资金流发生前或策略决策时已知的价格。

`ValuationEvent` 保留带时区的可得与生效时钟，以及永久禁止交易的语义。
窗口前估值在首个时点应用。窗口后的估值明确列为忽略，不延长模拟。
估值包括合法股票应收权益，但不会产生处置现金。
持仓价格缺失时财富未知，当日行情过期时日终净值仍然无效。

## 外部资金与收益

`CapitalFlow(event_id, available_time, effective_time, amount, source)`
声明以账户币种计量的有符号现金。金额必须有限且非零。
可得时刻必须带时区且不晚于生效时刻。
生效时刻必须处于模拟窗口内，并加入事件调度。会话窗口包含决策时点，
同步执行在提供决策策略时才将决策时点纳入窗口。
窗口前后资金流都会报错，不改写初始账户，也不静默忽略。
事件 ID 必须唯一，防止重复入账。
同一时刻的多个资金流按事件 ID 字典序处理，与输入排列无关。

存入增加现金，提取只能使用实际经济现金，不假定卖出所得，也不允许透支。
结果中的 `capital_flow_ledger` 记录时钟、来源、金额及前后现金和净值。
提供资金流后，日表新增 `capital_flow`、`cumulative_capital_flow`、
`pnl` 和 `cumulative_return`。
自起点累计盈亏等于净值减初始现金，再减累计外部资金。

收益按分段净值连乘：初始锚点为初始现金，增长因子为一。
每笔资金流发生前，将因子乘以 `pre_flow_NAV / anchor`，
再把锚点设为 `pre_flow_NAV + amount`。
日终收益为 `factor * daily_NAV / anchor - 1`，因此外部资金不计作投资收益。
分段估值使用先前观测，以及已经生效的永久估值，并包括未支付权益。
若持仓或股票权益缺少价格或当日观测，资金流前净值与后续累计收益均未知。
永久估值可持续使用，不要求每日重复声明。
仅日终价格过期时，只令当日收益未知。
资金流前财富、资金流后锚点或日终财富为零或负数时，不报告有效收益。
资金流边界一旦无法估值，后续收益保持未知。
不推断借贷、破产处置或可实际变现的期末价值。

## 延迟可见性与数量锁

报告快照包含现金、合法持仓、权益和未完成订单。
可见净值使用当前外部价格计算已送达的持仓与权益。
当前时点新增且未送达的财务变化会立即产生等待报告标记。
只要还有未送达报告，决策和订单进入两个环节都禁止提交新目标，即使策略要求交易。
撤单同步生效、确认延迟送达，不模拟网络撤单延迟。

`QuantityLock` 用 UTC 纳秒表示可得、开始和结束时钟，区间两端均包含。
限制在可得与开始时刻都到达后生效。
锁定期间公司行动可以增加合法股数，但只有锁定结束且原有 T+1、股票释放规则允许后，
这些股数才可执行。锁定会撤销剩余订单、跳过数量计算，并禁止在任何重叠行情柱成交。
解除锁定不恢复已撤销订单，零碎权益始终不可卖出。
锁定通知和生效保护随经济状态、已送达状态一同恢复。

## 检查点版本与失败处理

`minute-session.v3` 内嵌 `minute-financial-tapes.v1`、事件序列、事件游标、
权益、估值、资金流去重 ID、收益锚点、T+1 状态、母单费用、订单与成交、
策略快照、冲击和报告队列。浮点输入按实际使用的 Python 数值绑定，不截断小数精度。
输入、配置、策略实现及参与处理的账本辅助模块都绑定源码内容。
非有限诊断值使用显式标签保存。摘要用于检测意外损坏，不能防御能改写整个检查点的攻击者。

Platform 的版本 1 和版本 2 检查点会被拒绝，错误信息要求从原始输入重跑，或使用原先固定的源码运行。
缺少新状态不会被静默填默认值，不提供原地迁移。
任一步失败后，该会话禁止继续运行或保存检查点，必须丢弃并从上个成功检查点恢复。
同一时点中较早事件可能已经作用于失败对象，但该对象必须丢弃。
若修正输入，需要重新运行，因为检查点绑定了原序列。
已结束的会话不能保存检查点或再次运行，最终收盘权益和订单到期仍按原有结束逻辑处理。

测试在每个事件边界比较完整状态与最终财务表，并在零延迟情形下与同步接口对照。
这些是合成账务测试，不代表 Runtime 进程终止恢复或实盘券商恢复能力。

## Engine 归属与合成示例

此接口由 `quant-backtest-core[minute]` 显式提供，财务类型仅在 core 中定义。
Platform 当前仍保留原提供方；其类型、`LinearImpact` 与兼容别名在后续消费者切换时整体迁移。
不导入 Platform、Runtime 或模型训练依赖。此处尚未注册产品运行器的分钟后端。

从已安装 wheel 运行仓库中的合成 CNY 示例：

```bash
python -I -B examples/product/minute_session.py
```

示例包含公司行动、数量锁、报告延迟与外部资金，验证检查点恢复后的完整财务表。
[会话与资金流契约](../backtest/minute-session.zh-CN.md)说明时钟和恢复限制。
旧 `minute-session.v2` 必须使用原先固定的完整提供方环境，不允许改写摘要或静默迁移。
