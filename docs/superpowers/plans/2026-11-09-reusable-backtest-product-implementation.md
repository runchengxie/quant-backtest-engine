## Global Constraints

The following requirements are copied verbatim from the approved specification:

- Each run has exactly one financial owner.
- Different scenarios have independent accounts and state.
- The completed target has no runtime import from Engine into Platform, Runtime or private research.
- Keep the existing SDK namespace with its existing distribution.
- Use a distinct namespace for the extracted Python core rather than two wheels writing quant_backtest_engine files.
- The SDK base does not import the core; optional local-product invocation is explicit.
- Validate Python-core 3.12 and 3.13 explicitly; preserve SDK 3.11 compatibility.
- The public product envelope uses explicit decimal strings for monetary transport and string-safe UTC nanosecond clocks.
- Existing native v1/v2 integer-clock contracts remain unchanged; exact adapters perform conversion without JavaScript-number intermediates.
- Backend selection is explicit.
- There is no silent Rust-to-Python fallback or claim that a product's union of capabilities belongs to every backend.
- Requests cannot name arbitrary Python imports, executable commands or serialized code.
- Unknown is distinct from zero or an empty supported ledger.
- Impact already included in fill price is charged once.
- Cash fees are debited once.
- Benchmark/opportunity shortfall is descriptive and is not an additional debit.
- Deposits/withdrawals remain separate from PnL.
- Planned sale proceeds cannot finance unfilled buys.
- A failed financial step invalidates the live session; retain original failure and last successful checkpoint.
- Do not request another checkpoint from a poisoned owner.
- Old checkpoints stay on their original pinned provider/release environment.
- The pinned legacy environment includes the full Runtime/Go executable and dependency closure, not just the old Platform wheel.
- Every wave includes code, tests, canonical English documentation and its Chinese counterpart before the consumer switches.
- Provider merges/releases precede consumers.
- No wave combines ownership extraction with an unreviewed arithmetic/rounding/model rewrite.
- Keep compatibility aliases for at least two minor-release cycles and until every recorded supported consumer has migrated.
- No source-tree PYTHONPATH or editable-worktree import may masquerade as an installed-wheel test.
- Public examples are synthetic.
- No new tick acquisition, broker connection/orders, production configuration/scheduler changes, real cost/impact calibration, historical auction queues, real borrow/margin approval or prospective alpha evidence is authorized here.

Fixed version decisions: SDK `quant-backtest-engine-client` 0.2.0 becomes **0.3.0**, retaining import `quant_backtest_engine`; new `quant-backtest-core` owns only `quant_backtest_core`, with **0.1.0** at provider gate A, **0.2.0** at B, and **0.3.0** at C. Platform 0.0.1 becomes 0.1.0, 0.2.0 and 0.3.0 at its corresponding consumer gates. Runtime 0.1.0 becomes 0.2.0 with v9.
